PROJECT OVERVIEW
═════════════════════════════════════════════════════════════════════════════════

WHAT IS THIS?
  A silicon photonics neural processor that computes using light instead of electricity.
  
  Key features:
    • 8 spiking neurons implemented as optical interferometers
    • Photonic computation = 100× more energy-efficient than electronic GPUs
    • Tunable thresholds via thermo-optic phase shifters
    • Real-time spike readout via transimpedance amplifiers
    • USB interface for control and data acquisition

WHAT ISN'T INCLUDED?
  • The silicon photonics PIC chip itself (designed separately, ~6-12 months)
  • The 1550nm continuous-wave laser (external module, ~$200-1000)
  • PCB manufacturing (you provide Gerber files to fab, ~$150)

WHAT YOU'RE ACTUALLY BUILDING?
  → The control & readout board (this entire project)
  → The electronics that interface with the photonic chip
  → USB control software to run experiments
  → Simulation tools to validate the design

KEY DESIGN DECISIONS
═════════════════════════════════════════════════════════════════════════════════

1. PHOTODIODE TYPE: Germanium (Ge) integrated on PIC
   Why? Best responsivity @ 1550nm (0.8 A/W), mature technology
   
2. TIA OP-AMP: OPA2356 (1.4 GHz GBW, 1 pA input current)
   Why? Ultra-low input current (critical for pA-level photodiode), high bandwidth
   Alternative: LT6268 if OPA2356 unavailable
   
3. FEEDBACK RESISTOR: 10 MΩ (single-resistor design)
   Why? Provides 10 MV/A transimpedance gain (10 mV per µA input)
   Trade-off: Higher gain = lower bandwidth, but acceptable for photonics
   
4. COMPARATOR: LM393 (dual, open-collector)
   Why? Simple, reliable, low-cost threshold detection
   Alternative: OPA2333 (faster, but more expensive)
   
5. PHASE SHIFTER CONTROL: Thermo-optic
   Why? Mature technology, simpler drivers than electro-optic
   Trade-off: Slower response (~ms), but sufficient for neural learning
   
6. DAC: AD5684 (quad, 12-bit)
   Why? 2× gives 8 channels, SPI interface, low cost
   Alternative: AD8402 (rheostat, fewer controls)
   
7. USB INTERFACE: FT2232H
   Why? Dual-channel (SPI + UART/parallel), standard drivers, mature
   Alternative: CP2102 (simpler, single channel)
   
8. POWER SUPPLY: Single 3.3V rail with USB 5V input
   Why? Simplifies design, sufficient for all components
   Trade-off: Phase shifter heater power managed separately

   • Command: lsusb (Linux/Mac) or Device Manager (Windows)

   • Command: read 100 (monitor spikes for 100ms)
   • Should see: Spike counts for each neuron
   • If all zeros: Check comparator connections, threshold setting

Step 6: Characterize a neuron
   • Command: sweep 0 (sweep threshold for neuron 0)
   • Expected: Spike count increases as voltage decreases
   • Gives: S-curve showing neuron sensitivity

Estimated time: 2-4 hours (full integration)

CRITICAL SPECIFICATIONS TO REMEMBER
═════════════════════════════════════════════════════════════════════════════════

PHOTODIODE (on PIC):
  Responsivity: 0.8 A/W @ 1550nm
  Wavelength: Single-wavelength optimized (1550nm telecom band)
  Output: Current source (picoamps to microamps)
  Capacitance: ~50 pF (parallel)

TIA CIRCUIT:
  Feedback resistor: 10 MΩ (precision, 1% tolerance)
  Feedback capacitor: 50 pF (compensation)
  Transimpedance gain: 10 MV/A (10 mV per µA input)
  Bandwidth: ~160 MHz (-3dB)
  Noise: ~4 pA/√Hz (very low)
  Output swing: 0 to 3.3V

PHASE SHIFTER:
  Control voltage: 0 to 3.3V (12-bit DAC, 0.8 mV resolution)
  Heater power: ~50 mW per shifter (8 × 50 mW = 400 mW total)
  Response time: ~10 ms (thermo-optic is slow)
  Temperature coefficient: ~0.01°C/V (typical)

USB INTERFACE:
  Speed: 480 Mbps (HS USB 2.0) - far exceeds needed bandwidth
  Actual data rate needed: ~1 Mbps (8 neurons × 100 kHz spike rate)
  Power from USB: 500 mA (sufficient for all electronics)
  Protocol: SPI (DAC control) + UART (spike readout)

TROUBLESHOOTING GUIDE
═════════════════════════════════════════════════════════════════════════════════

ISSUE: Photodiode output has noise/oscillation
ROOT CAUSES:
  1. Feedback resistor trace too long
  2. Ground plane broken under TIA
  3. Digital noise from USB clock coupling in
  4. Op-amp instability (oscillation)
SOLUTIONS:
  1. Shorten Rf trace to < 2mm
  2. Check layer 2 is solid copper (no islands)
  3. Add via-stitching around TIA (2mm spacing)
  4. Increase Cf (feedback capacitor) from 50pF to 100pF, resimulate

ISSUE: USB device not recognized
ROOT CAUSES:
  1. FT2232H not soldered correctly
  2. USB driver not installed
  3. USB cable is power-only (not data)
  4. Windows/Mac doesn't auto-detect FTDI device
SOLUTIONS:
  1. Use oscilloscope to check D+/D- signals @ USB connector
  2. Download FTDI drivers from: https://ftdichip.com/drivers/
  3. Try different USB cable or port
  4. Try Linux (better FTDI support)

ISSUE: Spike counts always zero
ROOT CAUSES:
  1. Comparator threshold too high (no spikes reach it)
  2. Photodiode input not connected
  3. TIA output DC offset wrong
  4. Comparator not working (no supply voltage)
SOLUTIONS:
  1. Lower phase shifter voltage (set 0 0.5)
  2. Use multimeter to check photodiode input has ~nanoamp current
  3. Measure TIA output DC voltage with multimeter (should be ~1.5V idle)
  4. Measure comparator supply with multimeter (should be 3.3V ±0.1V)

ISSUE: Phase shifter voltage set but no effect
ROOT CAUSES:
  1. DAC SPI not connected
  2. MOSFET driver not working
  3. Heater resistor not on PIC (missing connection to PIC)
  4. Temperature sensor reading shows no heating
SOLUTIONS:
  1. Use oscilloscope to verify SCLK/MOSI signals @ DAC pins
  2. Check MOSFET gate voltage with multimeter (should be 0-3.3V)
  3. Verify heater leads are soldered to PIC connector
  4. Measure temperature with external thermometer on PIC

ISSUE: Design Rule Check (DRC) failing
COMMON ERRORS:
  1. "Trace too narrow" → Use 0.2mm minimum
  2. "Pad too close to trace" → Maintain 0.15mm clearance
  3. "Via under pad" → Move via away from component pad
  4. "Copper-to-copper short" → Check layer, reroute if needed
SOLUTIONS:
  1. Review each error in KiCAD
  2. Right-click error → Edit → Fix each one
  3. Re-run DRC until 0 errors
  4. If still stuck → Check design guide for examples
